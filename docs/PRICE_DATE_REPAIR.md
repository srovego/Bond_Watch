# Проверка и исправление дат котировок

Начиная с миграции 5, `price_observations.trade_moment` хранит подтвержденное MOEX ISS время сделки, если оно есть. Старые строки остаются в базе с `trade_moment=NULL`. Поле `dataversion.trade_date` относится к снимку таблицы ISS и не подтверждает дату `LAST`.

## Проверка

```bash
bond-watch backup
bond-watch price-audit --limit 200
bond-watch status
```

`price-audit` выводит строки без подтвержденного момента сделки, с несовпадением даты и момента, а также записи выходного дня для ручного просмотра. Запись за выходной день сама по себе не доказывает ошибку: если биржа проводила торги, нужен подтвержденный момент сделки. Проверяйте цену и номинал вместе с SECID и BOARDID в официальном ответе MOEX. Если архивный ответ не позволяет доказать, к какой дате относится уже сохраненная цена, оставьте строку без изменения. Новые опросы не переписывают старые котировки тем же моментом сделки.

## Исправление одной подтвержденной строки

Нужны точные значения из сохраненной строки и официальный источник с моментом сделки для того же выпуска, доски, чистой цены и номинала. Сначала выполните предварительную проверку:

```bash
python -m bond_watch.repair --db data/bond_watch.db --isin RU000A1095W4 --stored-date 2026-10-11 --trade-moment "2026-10-09 20:45:42" --clean-price 100.24 --nominal 1000 --evidence-url "https://iss.moex.com/iss/engines/stock/markets/bonds/securities/RU000A1095W4.json"
```

После сверки повторите ту же команду с `--apply`. Программа сделает отдельную SQLite-копию в `data/backups` и обновит только указанную строку. Она остановится, если цена/номинал не совпадают, на подтвержденной дате уже есть запись либо с прежней датой связано предупреждение. Такие случаи нужно разбирать вручную с резервной копией. Не запускайте исправление параллельно с `bond-watch poll`; согласуйте короткое окно обслуживания на VPS. Данные автоматически не удаляются.
